This is a comprehensive "Troubleshooting Bible" for building A2UI agents on the Vertex AI Reasoning Engine. It combines all findings from our stabilization sprints into generic, reusable patterns that can be applied to any ADK-based agent.

### 📘 The A2UI Reasoning Engine Troubleshooting Guide

| Issue Category & Name | Log/Browser Signature 🔍 | Generic Root Cause 🧠 | The Reusable Solution 🛠️ |
| :--- | :--- | :--- | :--- |
| **Model Access Lockout (404)** | `404 Publisher Model ... was not found`. Occurs even if the model name seems correct. | The project/region has either deprecated the model (e.g. Gemini 1.5) or restricted it to specific newer versions (e.g. Gemini 2.5/3.x). | **Implementation**: Never assume a model is available. Create a standalone `troubleshoot_access.py` and run a "probe" across the frontier (e.g., `gemini-2.5-flash`, `gemini-3.1-flash`, `gemini-3.5-flash`) to find the valid regional standard. |
| **Input Form Loop (Pattern Ghosting)** | Browser keeps showing the same input form again after submission. No errors in logs. | The agent is matching the high-level intent (e.g. "hi") but failing to recognize the transition to step 2 because the specific user action (e.g. "submit_form") isn't in its few-shot examples. | **Architectural Patches**: 1. Add intent-specific **examples** (e.g. "calculate route") to the `AgentSkill` card. 2. Refine **System Instructions** with a numbered "Turn Sequence" (Turn 1: Form, Turn 2: Calculation). |
| **State Persistence Gap (Context Loss)** | `NO STATE RECOVERED`. Model asks for data you just provided (e.g. "What is your address?"). | Reasoning Engine is stateless per request. If the UI sends a `userAction`, the ADK session history often doesn't automatically contain the *structured* data parts from the previous UI turn. | **The "Recovery Loop" Pattern**: In your executor's `execute()` method, manually iterate through `context.message.parts`. Recursively search for `userAction` objects and inject their `inputs` back into the prompt as a `[State: key=val]` block before calling the Runner. |
| **Protocol UI rejection (Missing Card)** | Browser says "Missing Card" or blank UI, but logs show the task completed successfully. | The UI expects a `DataPart` with a specific mimeType. If the agent returns raw text or the `jsonrpc` message is malformed, the renderer fails silently. | **A2UI v0.8 Compliance**: Ensure the executor wraps all JSON after the `---a2ui_JSON---` delimiter into an `a2a.types.DataPart` with `metadata={"mimeType": "application/json+a2ui"}`. Use regex to strip conversational text from the JSON. |
| **Cloud Serialization Error (Protobuf)** | `TASK_STATE_FAILED` or `PickleError` during deployment/execution. | Incompatibilities between local and cloud `google-cloud-aiplatform` versions, specifically with how Protobuf messages are unpickled. | **The Serialization Patch**: Add a monkey-patch to your deployment script that injects a `__setstate__` method into `google.protobuf.message.Message`. This handles missing `serialized` keys and prevents the runtime crash. |
| **Execution Context Flickering** | Permissions errors or "Project not found" randomly. | Reasoning Engine instances may lose environment variables if `aiplatform.init` isn't called explicitly inside the remote execution class. | **Forced Initialization**: Always use the **numeric Project Number** (e.g. `777979079027`) instead of the ID. Call `aiplatform.init` and `vertexai.init` inside the `__init__` AND the `execute()` methods of your executor. |
| **Chain-of-Thought Sequence Break** | Agent calls Turn 1 tools (Config UI) instead of Turn 2 tools (Optimization). | The agent's attention is focused on the conversational text (e.g. "hi") rather than the injected state data. | **Delimited Prompts**: When injecting state, append it to the query in a standardized format: `Actual User Text [State: param1=val|param2=val]`. Instruct the model to prioritize `[State]` data over user conversation. |
| **Dependency Build Failure** | Reasoning Engine deployment fails with "requirements not satisfied". | Version pinning conflicts (e.g. `pydantic v2` vs `v1`) or missing git-based dependencies for the A2UI SDK. | **Clean Build Strategy**: Avoid pinning `google-cloud-aiplatform` to a specific sub-version; let the engine resolve the closest compatible version. Use `@ git+https://github.com/...` syntax for side-loaded SDKs like A2UI. |
| **Echo Behavior Failure** | Tool JSON is swallowed or double-wrapped. | The agent is trying to be "helpful" by summarizing the tool output instead of echoing the raw A2UI string. | **Echo Constraint**: Add a hard constraint to the SYSTEM_INSTRUCTION: *"When a tool returns a string starting with '---a2ui_JSON---', you MUST include that exact string in your response without modification."* |

### 🚀 Best Practice Deployment Workflow
To avoid the trial-and-error loop for future agents, follow this sequence:
1.  **Verify Model**: Run the probe script to confirm the target region supports the chosen Gemini version.
2.  **Patch Serialization**: Include the Protobuf monkey-patch by default in the `agent_executor.py`.
3.  **Harden Protocol**: Use a regex-based unwrapper for `---a2ui_JSON---` to ensure text and data are separated.
4.  **Inject State**: Always implement the recursive history crawler to ensure multi-turn continuity.
5.  **Use Numeric IDs**: Use Project Number and specified Location persistently in all `init` calls.
